# 手机切换执行设备

iOS 0.7.4（38）请配套使用电脑和云端的 0.7.25 手机连接插件。手动切换仍然可用：点设备名，再选另一台设备，就是请求接管**当前会话**，不是复制任务。正在运行的工具先执行到可以核对结果的边界；若原任务在此之前正常完成，不再创建新的模型轮次。

## 0.7.25：双向自动无感接力（电脑 ↔ 云端）

手机设备菜单中的「断线无感自动接力」默认开启。手机在前台确认原设备离线后，会尝试连接已配对的另一端；对端确认可跟随后，手机打开**同一会话**。电脑离线可以跟随云端，云端离线也可以跟随电脑。手机只跟随，不重新发送原请求。关闭开关后恢复手动切换（电脑离线时提示是否转到云端）；这个开关不改变两端的执行租约。

两端 DSH 按同一规则决定谁能继续下一步：

- **正常退出**：关闭桌面 DSH（电脑仍开机）或正常停止云端服务时，源端封存可交接的活动轮次，生成 `auto-failover` 包并记录 `surrenders`。桌面退出时另起一次性 `--mailbox` 推送。对端收到交接、通过校验即可继续，不必等租约超时。Windows 后台收件箱也会在网络可用时补传检查点、已共享源码和云端结果；它不启动 DSH，也不替桌面续租。
- **断电、强杀或崩溃**：只有通过 `failover-v1` 两阶段确认的轮次才可超时接管。备用端确认 Offer，源端持久化 `armed: true` 并启用自熔断，备用端再确认 `peerArmed`。默认源端 12 秒没有有效续租就停止推进新步骤；备用端距最后有效续租满 20 秒后，才可依据已收到的检查点接管。`closeInterruptedTurn` 按 DSH 原生修复规则闭合中断边界，保留已完成步骤；`cloud-claims` 确保同一交接只领取一次。从未取得租约的离线新任务不会因此熔断。云端 DSH 崩溃时，即使 SSH 仍通，`--peer` 也不会凭过期的宿主心跳续租，电脑可以反向接管。

两端 `taskSync.turnRelay: true` 时默认启用自动接管，`autoFailover: false` 可关闭。调整 `sourceFenceMs` / `takeoverDelayMs` 或升级云端脚本、Windows 收件任务，见[云端部署说明](../deploy/cloud/README.md#升级两端与后台收件箱)。

## 工作区与源码

在原工作区用 `/source-share src tests` 登记允许两端同步的源码，也可以在专用工程中使用 `/source-share --project`。该授权不会从聊天文字、仓库内容或手机切换动作中推断。同步范围是保存到磁盘、符合共享规则的源码；不包括未保存的编辑器缓冲区、进程内存或任意附件。已绑定时，接管端必须收到并应用指定源码修订；有冲突就等待。两端均未绑定时，允许只接力会话上下文，不表示工程文件已到达。

源端记录工具边界和源码版本，目标端核对版本、会话、权限及执行回执。云端为已登记的源码保留本地私有裸 Git 仓库：接管前生成恢复点，后台也会检查变更（约 30 秒一次）。它不会改工程的分支，不会推送到 GitHub。源码共享的授权仍需慎重：请勿在普通源码文件中硬编码密钥。

## 执行与回执

手机等待目标 DSH 接受原任务后才切换。重复选择或重新打开手机端会复用同一笔未确认请求。首轮模型请求自动附上环境和进度快照。`relay_environment` 可复查 Windows ↔ Linux 的工具映射（如 PowerShell ↔ Bash）、工程技术栈缺少的命令及源码共享状态；不会自动安装工具。工具返回成功并不等于部署成功；需要用原部署编号或目标系统状态核实。无法核实的操作不能仅凭没看到输出就再发一次。

`taskProgress` 给出下一步：有工具结果就复用（`use-result-do-not-repeat`）；未启动的调用可在目标端规划（`plan-on-target`）；无结果的只读调用可以重查（`refresh-with-read-only-tool`）。写文件或有外部副作用的调用若已发出但没有回执，保留 `TOOL_OUTCOME_UNKNOWN`，按 `verify-before-retry` 的 `verifyHint` 核对文件修订或外部目标回执，不盲目重放。

云端已持久收到交接和所需源码后不依赖原 DSH 在线。若断电发生在交接或源码送达之前，不能把最近一次历史截图当成新的执行权。另一个原生会话写入器仍占用目标时也不强行覆盖；手机保留原连接并报告交接未确认。这是会话步骤接力，不是进程内存迁移；断电前未落盘或未传出本机的字节，另一端无法恢复。
