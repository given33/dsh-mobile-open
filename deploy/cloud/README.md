# 普通 DSH 会话的跨设备共享

共享属于「手机连接」桌面插件。直接在 DSH 原来的工作区新建或打开会话；不需要单独安装“共享任务”插件、打开浏览器或移动任务。手机连接电脑时看到的就是桌面 DSH；连接云端时使用同一个会话 ID 查找已同步的历史。手机的「新建会话」留在当前执行端。

在已经配对的两台主机上，给现有 `id: mobile-link` 的 `config` 加 `taskSync: {role: desktop, sshHost: your-verified-ssh-alias}`（电脑）或 `taskSync: {role: cloud}`（服务器）。没有这个配置的安装不会上传任何会话。将插件自带的 `desktop/lib/task-sync/transfer.py` 安装到云端 `/opt/dsh-cloud/task-transfer.py`。保留原 `mobile-link` 家庭配对配置和受信 SSH 主机密钥。升级旧部署时禁用旧 `shared-sessions` 配置；不要删除原工作区或历史文件。

* 两端读取已注册工作区，使用 DSH 自己的会话存储接口。原来的工作区 ID 与显示名称决定对端映射，同名工作区不会合并。远端路径不会作为本机目录使用。
* 历史使用原始会话 ID、事件、工具结果、时间和分支元数据。已同步的完整轮次可以在另一台机器上打开。历史是任务数据，可能含聊天中粘贴的秘密或工具输出；只发给配对的私人服务器，不进入代码仓库。不会复制整个项目目录、模型凭据文件或附件文件库。
* 在一端正在执行或持有写锁时，不在另一端重放工具。只向原生会话追加经校验的完整轮次；未完成的进度保留在同步收件箱。两端历史分叉时保留双方记录，不强行覆盖。同步不是 Windows 进程迁移，电脑断电不会让本地命令自动在 Linux 接着运行。
* SSH 短暂断线后自动补传；周期为 12 秒，真实延迟还受历史大小和网络影响。首次导入保留归档标记；删除不跨端传播。云端 DSH Web 服务仍只监听回环地址，不公开 owner 接口。

上游无法迁移的 v3 历史按原格式保留：只替换云端的工作目录头，后续压缩事件字节不变，不补造缺失的工具结果。桌面与云端会有相同的迁移限制。
