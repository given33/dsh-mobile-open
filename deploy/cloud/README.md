# 普通 DSH 会话的跨设备共享

共享属于「手机连接」桌面插件。直接在 DSH 原来的工作区新建或打开会话；不需要单独安装“共享任务”插件、打开浏览器或移动任务。手机连接电脑时看到的就是桌面 DSH；连接云端时使用同一个会话 ID 查找已同步的历史。手机的「新建会话」留在当前执行端。

在已经配对的两台主机上，给现有 `id: mobile-link` 的 `config` 加 `taskSync: {role: desktop, sshHost: your-verified-ssh-alias}`（电脑）或 `taskSync: {role: cloud}`（服务器）。没有这个配置的安装不会上传任何会话。将插件自带的 `desktop/lib/task-sync/transfer.py` 安装到云端 `/opt/dsh-cloud/task-transfer.py`。保留原 `mobile-link` 家庭配对配置和受信 SSH 主机密钥。升级旧部署时禁用旧 `shared-sessions` 配置；不要删除原工作区或历史文件。

* 两端读取已注册工作区，使用 DSH 自己的会话存储接口。即使没有会话，工作区也会出现在另一端。同步身份是创建端与原始工作区 ID 的组合：重命名不改变身份，同名项目也不会误合并。原工作区改名后，副本在下一次目录核对时更新名称。远端路径不会作为本机目录使用。
* 历史使用原始会话 ID、事件、工具结果、时间和分支元数据。已同步的完整轮次可以在另一台机器上打开。历史是任务数据，可能含聊天中粘贴的秘密或工具输出；只发给配对的私人服务器，不进入代码仓库。不会复制整个项目目录、模型凭据文件或附件文件库。
* 在一端正在执行或持有写锁时，不在另一端重放工具。只向原生会话追加经校验的完整轮次；未完成的进度保留在同步收件箱。两端历史分叉时保留双方记录，不强行覆盖。同步不是 Windows 进程迁移，电脑断电不会让本地命令自动在 Linux 接着运行。
* 工具调用、工具结果和步骤结束都会触发增量发布，不必等到轮次结束。电脑与云端通过同一条已校验主机密钥的 SSH 连接双向轮询，正常间隔 1.5 秒；每 12 秒仍做一次工作区全量核对。SSH 不通不会堵住本机记录，也不会阻止另一端读取已经送达的记录。这些间隔不是接管时限，更不是同步提交保证。
* 排队的输入有时出现在 `turn/start` 之前。它和没有结果的命令一样，只保留在检查点，不注入备用端的可执行队列。在结果未知时，不能仅根据心跳超时重跑命令；完成部署、扣款等操作后，执行端也可能来不及写回结果。
* 普通、置顶、归档是同一个会话的三种互斥状态。两端均可更改；逻辑版本保存在本机，重启或收到旧包不会把已同步的新操作撤销。归档仍服从 DSH 原生运行保护；删除会话或真实项目不会跨端传播。云端 DSH Web 服务仍只监听回环地址，不公开 owner 接口。

上游无法迁移的 v3 历史按原格式保留：只替换云端的工作目录头，后续压缩事件字节不变，不补造缺失的工具结果。桌面与云端会有相同的迁移限制。

### 云端跟随电脑的模型设置

在已启用上述配对同步的主机上，不必在云端再建一套模型列表。插件使用 DSH 原生设置接口，将电脑的自定义供应商、HTTPS Base URL、模型能力、默认模型和推理强度**单向**同步到云端；修改或移除配置、断线重连后也按电脑的设置核对。已有会话保留自己的模型选择，云端不会把自己的默认模型倒写到电脑。修改在服务端生效，不需要更换手机 App。

两端仍使用各自的凭据库。同步只包含 API Key 的引用名，不包含密钥值、登录令牌、Cookie 或自定义 HTTP 请求头。需要相应凭据的云端供应商必须先在该服务器上配置凭据。包含用户名、密码或查询参数的 Base URL 不参加同步；有私有请求头的云端供应商不会被自动移除或改绑到其他端点。云端离线时继续使用最后一次成功应用的设置。

在云端或电脑给工作区改名，改的都是原来同一个工作区。两台机器同时离线改名时按保存的逻辑版本合并，手机不会因此多出一行。没有「本地」或「云端」分组。

### 从旧版“来自……”分组迁移

先停用旧的独立共享插件。核对两端原生注册记录与 `mobile-task-sync/routes` 中的来源，记录旧分组的**创建端工作区 ID**，不要用展示名筛选或直接修改 `storages/workspace.json`。两端的 `DSH_HOME/mobile-task-sync/retired-workspaces.json` 使用同一份清单，例如：

```json
{"desktop":["old-desktop-workspace-id"],"cloud":["old-cloud-workspace-id"]}
```

这份清单仅存在于个人部署，不进公开仓库。插件按原始身份识别旧分组及其副本；只注销空项目或仅含初始权限设置的草稿，并保留目录和会话文件。若有已打开的会话、真实消息、工具记录或不可读历史，则保留注册，不自动迁走或合并。迟到的旧目录和旧会话包不会重新生成这些分组。

接力的验收条件是另一端能用原会话 ID 打开已落盘的轮次、生成下一轮，并把结果写回原工作区。跨主机的工作区路径不同；要在两端操作同一份工程文件，必须另外准备经授权的同步目录或仓库检出。不要把整块磁盘、个人配置目录或模型凭据当作要自动上传的工作区内容。

### 0.7.10：在原会话提交可离线的云端任务

在配对两端的 `taskSync` 配置中分别启用 `cloudTurns: true`。电脑端选择已有会话，在「手机连接 → 本会话云端执行」填写任务。无需另建工作区。这个入口提交**新的一轮**；不会抢占或重跑正在执行的本地命令。手机也可以直接在同一会话的云端设备上发送消息。模型密钥和工作目录内的实际文件需要预先在云端就绪，不会随任务自动上传。

电脑插件先保存原生会话与用户提交记录，再由已配对的 SSH 传输把这份委托交到云端。普通历史快照不会触发执行。云端核对会话前缀、归档状态和委托身份；有分叉不覆盖，有未释放的本机写入者不抢锁。云端在调度前持久化唯一领取记录，遇到结果不明的提交不自动重跑。未领取的委托在 15 分钟后失效。「本机登记」不等于「云端已开始」：如果原电脑可能立即完全断电，要以云端同一会话出现这一轮为准。首次从已打开且正在写入的云端会话向电脑反向接管，不在这个功能的保证范围内。

Windows 可在同一个 DSH 用户下运行插件内 `tools/windows-cloud-inbox.ps1 -SshHost <已校验主机密钥的 SSH 别名>`。独立的 Windows 计划任务在该用户登录后每分钟补投已登记的云端任务、接收云端结果；不会启动桌面 DSH。电脑断网时结果留在云端。恢复网络后，即使桌面程序未启动，收件箱也会落盘；下次打开 DSH 时才导入原会话。使用 `-Disable` 可移除计划任务，保留已收到的数据。若需 Windows **登录前**开始收件，可由管理员在相同用户身份下使用 `-BeforeSignIn`；须验证该账户在非交互会话能使用指定 SSH 身份。不要把用户密码、SSH 私钥或模型密钥写入脚本。

### 0.7.11：普通终端步骤的接力（Windows → Linux，不用虚拟机）

这不是远程终端，也不是把一个 Windows 进程恢复成 Linux 进程。在配对主机的 `taskSync` 中设置 `portableSteps: true` 后，标准模式会话内符合下表的前台 PowerShell / Bash 命令会自动登记，不需要先提交 `/cloud-run`。不支持持久终端、后台作业、提权、嵌套 PTC 调用、自定义工作目录和任意脚本。其他命令照原样在本机运行，不会自动在云端重放。

| 命令形式（示例） | 接力的工作 |
| --- | --- |
| `Start-Sleep -Seconds 5` / `sleep 5` | 用云端登记的到期时间，只等剩余时间 |
| `Write-Output '完成'` / `printf '%s\n' '完成'` | 产生指定文本；不执行文本内容 |
| `(Get-FileHash -LiteralPath 'relay-inputs/data.bin' -Algorithm SHA256).Hash` / `sha256sum -- 'relay-inputs/data.bin'` | 对登记时的文件内容重新计算 SHA-256 |
| `(Get-Item -LiteralPath 'relay-inputs/data.bin').Length` / `wc -c < 'relay-inputs/data.bin'` | 取得登记时的文件字节数 |

可以在后三类操作前加一段等待，例如 `Start-Sleep -Seconds 5; (Get-FileHash -LiteralPath 'relay-inputs/data.bin' -Algorithm SHA256).Hash`。登记文件必须是工作区根目录 `relay-inputs` 下的非链接普通文件，单文件不超过 1 MiB；不要把秘密放进去。**这是命令接力输入的限制，不是手机附件的大小限制。** 只有命令指定的那个文件会传输；插件不扫描或上传整个工程。若文件在登记后发生修改，云端使用登记时的版本。

云端把步骤和输入持久化后，本机才开始执行登记的命令。在发出登记前就发现备用端不通时，普通命令仍在本机运行，但没有断电保护。若发出登记后丢失确认，则不重复启动。如果命令已经在本机真实完成，备用端掉线不抹掉本机的真实结果。租约每 2.5 秒续一次，超过 10 秒未续就拒绝旧执行者提交；独立云端服务每秒检查到期步骤，不依赖桌面 DSH 或 SSH 连接存活。只读计算可以重复，但同一会话、同一调用只接纳一份最终回执。网络分区不能强行停掉另一端已有的进程。接力回执与 DSH 原生工具结果分开存储，不伪造对话、不自动对有副作用的命令补跑。

在原会话输入 `/relay-status` 查看最近十条回执；桌面关闭时已安装的 Windows 收件箱仍能下载回执，下次打开即可查看。云端完成一个终端步骤不等于自动跑完其余模型步骤。Windows 用户明确取消并成功送达云端的步骤不再接力；如果机器断网导致取消未送达，云端仍可能完成已登记的只读计算。

部署：在已配对的 DSH Linux 主机上，将本版本 `portable_worker.py` 和 `transfer.py` 分别安装到 `/opt/dsh-cloud/portable_worker.py`、`/opt/dsh-cloud/task-transfer.py`；将 `dsh-portable-steps.service` 安装为 systemd 服务并启用。需要已存在且归 `dsh-cloud` 所有的 `mobile-task-sync` 目录。服务以 `dsh-cloud` 用户运行，不开公网端口。桌面更新插件后重新注册随包的 Windows 收件箱，才能在桌面关闭时接收新格式的回执。旧版正常会话同步不依赖这个服务。

### 0.7.12：让另一台 DSH 接管后续模型轮次（双向）

两端更新插件和任务传输脚本，并分别在已配对主机的 `taskSync` 配置中打开 `turnRelay: true`。未开启的主机不注册接力工具，也不会因为同步了一段聊天记录而执行它。普通用户不需要另外创建云端工作区。

- `relay_environment` 只读：在执行端报告 OS、架构、当前工作目录、DSH 原生 Shell 工具、PATH 上发现及未发现的程序，以及项目根目录的依赖清单。不输出环境变量和密钥，也不把「发现 npm」当成「这个项目的依赖已安装」。
- `relay_remaining_task` 由模型在独立步骤里调用。接力包必须含真实的工具成功结果，以及同一步、同一轮的正常结束事件；有正在运行的后台作业、排队输入或同时发生的其他工具调用时不交接。接手端只在原会话、匹配的历史前缀及兼容的权限下提交固定的继续消息，之后由原生 DSH 调模型、执行工具和请求审批。不会将工具输出当作新的用户命令，也不会因为模型自己的接力提示来回切换。
- 若需要把少量工程文件随步骤一起交付，在**源设备** DSH 的 `mobile-task-sync/relay-inputs.json` 显式列出允许的输入。例如 `{"desktop:<原工作区 ID>":["package.json","build.cjs"]}`。配置文件在工作区外。仅支持工作区根目录的普通文件（最多 32 个，合计 1 MiB），不追随链接，不递归扫描。没有此配置时不传文件。接手端校验字节和 SHA-256，在受管工作区仅创建缺失文件，不覆盖不同版本；回到原工作区只校验，不写入。大型工程和原生依赖仍需分别准备。
- 已落盘的接力包可以通过后台收件箱转送；**尚未传到另一端时**突然断电，另一端不能凭空重建这个包。接手后原设备离线不影响接手端后续轮次，结果仍由普通会话同步带回。原生运行时还持有同一会话写入权或两端历史不同，不强行拼接历史。收到相同接力包不重复提交；执行确认丢失不自动重试有副作用的整轮任务。首轮领取有效期 24 小时。

**这是任务交接，不是搬运进程内存。** 跨平台验收使用两端隔离的 DSH 和可复现的模型响应：在源端生成交接包并关闭源 DSH，目标端从空的受管工作区接收两个获准的输入文件，调用环境工具、执行一次实际的 `npm run build`，再调用模型生成最终回复。这个测试不代表已经运行到一半的任意构建、安装、部署或任意脚本能在断电后从下一条 CPU 指令继续。不能确认外部写入是否成功时，先查询目标系统，不能盲目重放。

### iPhone 的公网云端入口

移动端在设备名下方列出同一配对中的电脑与云服务器。电脑 `mobile-link/family-route.json` 的可选 `displayName` 是给手机显示的设备名称（例如「阿里云 ECS · 广州」），不影响公钥、设备 ID 或授权。旧配置只返回「云端」时，手机用云服务器加设备 ID 短尾区分。

自签名证书配合 sslip.io 时，将云节点域名设为 `<以连字符分隔的 IPv4>.dsh-cloud.sslip.io`。在现有 TLS 透传入口为它配置与旧云域名相同的 SNI 后端，保留原域名，再修改电脑的 `endpoint`。先从公网验证新域名的叶证书 SPKI 和 `/mobile/v1/hello` 身份均与原授权一致。不要把流量送到桌面中继、公开云端 DSH 管理端口，或让客户端学习网络上第一次看到的公钥。其他自有域名可使用系统信任的有效证书和与授权一致的公钥；本 App 没有为整个 sslip.io 或所有公网域名放开 ATS。

### 0.7.14：接管后读取执行记录

接管端的 `relay_environment` 除了报告当前平台、工具和目录，还会从这个会话的原生日志读回最近一次接力的源端步骤：用户请求、工具调用及结果的事件序号，哪些工具报错、哪些缺少结果。最多返回最近 32 个工具调用，并报告省略数量；不额外复制命令参数、正文或凭据。仅被动同步来的历史不会被当成本机刚接管的任务。

如果接管端尚未提交新轮次就取消，保存在收件箱的任务可以重试。若提交后丢失确认，插件按原生请求 ID 核对同一会话的新收件或用户消息记录，不会再次派发同一任务。这个确认只表示 **DSH 收到了请求**，不表示部署或安装成功。没有可核对的记录时保留待查，不盲目重跑。这是步骤边界的接力，不是断电后迁移进程内存。

### 0.7.15：核对 Git 发布是否已经提交

这项功能面向**已明确接入的自管裸 Git 仓库**，解决「发布分支已更新，但发送端没收到回执」的问题。它不会修改现有仓库、托管平台的保护规则或 CI，也不把普通 `git push` 自动替换成发布。没有目标配合的部署，不能凭进程退出码断定成功或失败。

**一次性接入条件（由仓库管理员完成，不交给模型自行放宽权限）：**

- 服务端支持原子推送，并能运行 `reference-transaction` 钩子。在启用保护之前建立发布分支、创建仓库独有的身份对象，用 `refs/dsh-relay/identity` 固定其完整对象 ID。设置仓库本地 `dshRelay.protectedBranch` 为这个分支名。复制插件里的 `tools/relay-git-guard.mjs` 和它引用的 `lib/task-sync/git-release.mjs`，保留相对路径；让原有钩子在 `prepared` 阶段把**同一份完整标准输入**和阶段参数交给该守卫，任一检查失败均须拒绝事务。不要覆盖旧钩子。守卫启用后，直接改写发布分支、删除或重写接力回执、轮换仓库身份都会被拦截。先用新建的测试仓库验证，再由管理员决定是否接入正式分支。
- 两端均需有该仓库的 Git 客户端、已有的读写授权和单一指向同一仓库的读写 remote，并分别设置仓库本地 `dshRelay.<remote>.identity` 与 `dshRelay.<remote>.branch`。这不是系统级配置。CI 必须只监听正式发布分支，**不要监听** `refs/dsh-relay/` 下用于暂存对象和保留回执的内部引用。保留这些引用供设备掉线后核对，勿擅自清理。

**一次发布如何接力：** DSH 的 `relay_git_release_plan` 将目标身份、分支、原提交、期望提交和稳定操作编号写入原会话，不执行推送。两端通过原生 Shell 和已有审批调用 `relay_environment` 给出的当前主机脚本路径：

```text
node <脚本路径> <prepare|status|finish> <remote> <分支> <原操作编号> <仓库身份> <原提交> <期望提交>
```

`prepare` 只把计划和提交对象保存到目标仓库，不动发布分支。另一台机器即使没有原工作树，也可以用 `status` 查询原操作，`finish` 从已准备的目标取回对象，再原子地更新分支和创建不可覆盖的回执。只允许从预期版本向前更新；已有匹配回执则只读返回，哪怕分支已推进到更高版本。目标不可达、分支被其他操作更改、身份或回执不符时，不以重新推送试探结果。`committed` 只证明 Git 引用事务提交了，**不证明下游应用已部署成功**。后者必须另外核对发布平台的运行记录。

用于验收时，可将 `deploy/cloud/create-release-sandbox.py <全新目录> <已安装的 relay-git-guard.mjs 路径>` 作为普通用户运行。它只新建空的本地裸仓库和测试发布分支，输出身份和初始提交，不会接入产品部署、不打开监听端口，传入已存在目录会直接失败。
